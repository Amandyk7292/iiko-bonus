# Обновление плагина через кассу

Первый выпуск с установщиком — 1.13.0. Его один раз устанавливают обычным способом, сохраняя конфигурацию и данные. Последующие выпуски кассир проверяет и скачивает через меню Bulka, затем закрывает iikoFront и ждёт завершения установки. В обычной установленной среде iiko требует остановки/запуска Front для обновления плагинов: [официальная документация](https://iiko.github.io/front.api.doc/debugging.html). Принудительное завершение процессов и аварийный перезапуск не используются.

## Выпуск следующей версии

1. Изменить версии в IikoBonusPlugin/IikoBonusPlugin.csproj и BulkaPluginUpdater/BulkaPluginUpdater.csproj, подготовить инструкцию версии и зафиксировать исходники.
2. Запустить scripts/build-iiko-plugin.ps1 с отдельным OutputDirectory. Обязательные наборы включают проверку подписанных пакетов и установщика.
3. Запустить scripts/package-iiko-plugin-update.ps1 с BuildDirectory и SigningKeyFile. Ключ подписи хранится вне репозитория и рабочего веб-сервера; в исходниках содержится только его открытая часть. Сохранить защищённую резервную копию ключа отдельно; потеря ключа потребует первоначального ручного обновления доверия на кассах. Ключ подписи не является SSH-ключом.
4. Зафиксировать созданные public/downloads/BulkaPlugin-VERSION-update.zip, .zip.sha256 и -update.manifest.json. Внутри ZIP ровно DLL, Manifest.xml и BulkaPluginUpdater.exe. Файлы конфигурации и данных не включаются. Версионные артефакты не перезаписываются.
5. Опубликовать весь релиз обычным проверенным порядком. Указать его версию и локальную ссылку на ZIP в существующей политике «Кассы и интеграции»; либо применить условную миграцию, сохраняющую minimum/enforcement.
6. Проверить публичные байты архива, подпись манифеста, endpoint с тестовой привязанной кассой и версию после установки на отдельной кассе.

Маршрут GET /api/loyalty/pos/updates/latest использует обычную авторизацию кассы и её точки. Старая авторизованная версия может проверить обновление даже при включённом минимуме; финансовые и складские операции остаются ограниченными политикой.

Подпись RSA PKCS#1 SHA256 покрывает UTF-8 domain `BulkaPluginUpdate:v1\n` и исходные декодированные байты payloadBase64. Подписаны версия, API, неизменяемый URL, размер/SHA256 архива и полный трёхфайловый инвентарь. Проверка подписи выполняется до загрузки и повторяется установщиком. Открытый ключ из ответа сервера не принимается. Загрузка не следует перенаправлениям и не передаёт токены в запрос архива.

Установщик AnyCPU net472 открывает дескрипторы Front/host и проверяет время создания процесса. Он ждёт завершения обоих процессов, проверяет папки и текущую версию, сохраняет резервные файлы и журнал транзакции, меняет только разрешённые файлы. При прерывании есть явное восстановление через --recover. Подробности и команда восстановления — в BulkaPluginUpdater/README.md. Автоматический откат после произвольной функциональной ошибки уже запущенной новой версии не реализован; перед общим распространением нужен запуск на одной кассе.

.NET 4.7.2 требует Windows 7 SP1 или поддерживаемую более новую Windows: [Microsoft](https://learn.microsoft.com/en-us/dotnet/framework/get-started/system-requirements). Физическая проверка всех ОС/касс отдельно от локальных тестов обязательна перед утверждением такой совместимости.
