# Автоматическое подтверждение телефона Bulka

Подготовлены официальный WhatsApp через Cloud API или YCloud и SMS через
Mobizon Kazakhstan или AutoCall. Клиент вводит номер и нажимает «Подтвердить номер»;
сервер отправляет код без команды боту. `CUSTOMER_OTP_PROVIDER` задаёт канал входа.
Восстановление пароля использует одноразовую ссылку из SMS AutoCall, без кода
или WhatsApp. Регистрация может использовать отдельный канал через
`CUSTOMER_REGISTRATION_OTP_PROVIDER`; пустое значение сохраняет общий канал.
Поддерживаются номера Казахстана в диапазонах +76 и +77.

По умолчанию `CUSTOMER_OTP_PROVIDER=legacy_whatsapp`: действующая регистрация
остаётся доступной, пока официальный провайдер не подключён и доставка не проверена.
Остальные функции WhatsApp (поддержка, сотрудники, курьеры) не отключаются.

## AutoCall: SMS только для регистрации

4 октября владелец разрешил включить регистрационные SMS через AutoCall и убрать
подтверждение регистрации через WhatsApp. Текущий согласованный режим регистрации —
SMS с шестизначным кодом. При установке этого обновления в окружении сервера выбирается
`CUSTOMER_REGISTRATION_OTP_PROVIDER=autocall_sms`; `AUTOCALL_API_TOKEN` хранится только
в серверном окружении. Доставка была проверена на контролируемом номере 3 октября.
`CUSTOMER_OTP_PROVIDER` сохраняет текущий провайдер входа и восстановления пароля.
Значение `CUSTOMER_OTP_PROVIDER=autocall_sms` сервер намеренно отвергает: AutoCall
подключён только как регистрационный канал. Пустой регистрационный override
использует общий провайдер. При включённом регистрационном AutoCall старые клиенты
без `otpDeliveryVersion: 2` получают `400 OTP_CLIENT_UPDATE_REQUIRED` с просьбой
обновить приложение или перезагрузить страницу. Сервер не создаёт WhatsApp-запрос,
не резервирует SMS-лимит и не отправляет код. Совместимый клиент получает
`deliveryMode: automatic`, `channel: sms`, `codeLength: 6`, срок 300 секунд и
пустые WhatsApp-поля. Старые клиенты входа и восстановления сохраняют прежний режим.
Общий `/api/auth/request-otp` при включённом регистрационном AutoCall также возвращает
`400 OTP_CLIENT_UPDATE_REQUIRED` для неизвестного номера или незавершённого профиля
до создания WhatsApp-запроса, отправки кода или резервирования лимита. Для уже
зарегистрированных клиентов общий вход по коду сохраняется.
Завершение `/api/auth/register` при этом требует подписанный регистрационный токен
с grant пароля, созданным после подтверждения кода регистрационного потока.
Старый токен из общего WhatsApp-входа без такого grant возвращает тот же
`400 OTP_CLIENT_UPDATE_REQUIRED` до создания профиля, записи согласия, реферальных
наград или премии кассиру. Обычный вход и восстановление пароля не ограничиваются
этой проверкой.

Запрос: `POST https://autocall.kz/api/v1/bulks`, Bearer-токен в заголовке,
JSON с `name: "Verification code"`, `list_id: [{ number: "+770…" }]` и коротким
текстом `Bulka: код 123456. Действует 5 минут. Никому не сообщайте.`.
Текст укладывается в один кириллический SMS-сегмент. Код подставляется цифрами,
без переменных вида `{{code}}` или имени отправителя. Сервер автоматически добавляет
`date_from` и `time_from` из одного снимка текущего времени `Asia/Almaty`,
чтобы SMS запускалась сразу; клиенту не нужно выбирать дату или время.
Контролируемый запрос 3 октября с пропущенными полями в кабинете получил запуск
на следующие сутки, поэтому документированный режим «по умолчанию сейчас»
для регистрационного OTP не используется.

У нового аккаунта первая SMS-рассылка может попасть на модерацию; одобрение
обычно занимает рабочий день. После одобрения фиксированный текст с меняющимся
кодом из 4–6 цифр не требует повторной проверки. Ограничения времени доставки
конкретного тарифа проверить в аккаунте перед включением.
Сервер принимает `201` с положительным числовым ID, статусом `running`,
одним получателем и одним сегментом. Ответ `completed` принимается только
с точным текстом отправленной SMS и единственным сообщением `delivered`,
связанным с этой рассылкой и нужным номером. `moderation`, `awaiting`, `denied`
и неверные ответы не активируют код. Ответ `running` подтверждает принятие рассылки,
а не доставку клиенту. Если создание вернуло `generating`, `awaiting` или
`moderation`, сервер делает не более
десяти чтений `GET /bulks/{id}` с интервалом 500 мс, сохраняя тот же ID и общий
таймаут 15 секунд. Эти промежуточные статусы могут кратко появляться до запуска
обработчика AutoCall. Код активируется только после `running` или подтверждённой
доставки `completed`; оставшийся промежуточный статус считается неподтверждённой
отправкой, включая ожидание модератора или будущего времени запуска.
`POST` не повторяется. Таймаут или ошибка не вызывают
повторный платный запрос; провайдерные детали, код и токен не прикрепляются
к ошибке приложения.

До включения установить миграцию `20261002150000_automatic_customer_otp.sql`
и совместимый клиент, проверить получение и однократное подтверждение SMS
на контролируемом номере, затем задать согласованный дневной лимит.

## Восстановление пароля по SMS-ссылке

`POST /api/auth/password-reset/start` сохраняет совместимый запрос с `phone`,
`token` и необязательным `otpDeliveryVersion: 2`. Для любого допустимого номера
ответ имеет одинаковые поля: `success: true`, `deliveryMode: "sms_link"`,
`channel: "sms"`, `expiresInSeconds: 900`, `retryAfterSeconds`.
Первый запрос обычно возвращает ожидание 60 секунд. После второго запроса
`retryAfterSeconds` сразу сообщает время до освобождения первой попытки в
скользящем 24-часовом окне (до 86400 секунд).
Ответ не содержит сведения о наличии аккаунта, URL, код или токен ссылки.
Неизвестному номеру отправляется такой же текст; его ссылка не может изменить
чужой или позднее созданный аккаунт. Это сохраняет одинаковое поведение отправки
и исключает проверку наличия аккаунта через публичный запрос.

Ссылка имеет вид `https://bulka.com.kz/reset-password#reset=<64 lowercase hex>`.
Сервер генерирует 32 случайных байта, хранит только SHA-256 хеш и привязывает
его к номеру, аккаунту и текущей версии авторизации. Срок — 15 минут с создания,
включая время отправки и модерации. Повторная отправка заменяет предыдущую ссылку.
Страница очищает фрагмент URL до сетевого запроса и отправляет токен только
в теле `POST /api/auth/password-reset/validate-link` или
`POST /api/auth/password-reset/complete-link` вместе с новым `password`.
Проверка не расходует ссылку. Истёкшая, чужая, использованная или отменённая
ссылка возвращает единый `PASSWORD_RESET_LINK_INVALID`.

Одноразовое использование, смена пароля, увеличение `auth_version` и отзыв
refresh-сессий выполняются одной транзакцией с блокировками строк. После успеха
клиент входит вручную. Восстановление детского пароля родителем сохраняется.
Старый `POST /api/auth/password-reset/complete` с OTP закрыт ответом
`410 PASSWORD_RESET_SMS_LINK_REQUIRED`; назначение `customer_password_reset`
больше не создаёт OTP и не принимается общим подтверждением кода.

AutoCall получает постоянный шаблон
`Bulka: Novyi parol: {{reset_url}} (15 min)` и значение ссылки в
`list_id[0].variables.reset_url`. После подстановки текст — один ASCII SMS-сегмент
до 160 символов. Дата и время запуска автоматически задаются сервером по
`Asia/Almaty`. Используется тот же серверный `AUTOCALL_API_TOKEN`; отдельного
провайдера или WhatsApp fallback для восстановления нет.
До установки требуется миграция
`20261004180000_customer_password_reset_links.sql` и
`20261004181000_customer_password_reset_rolling_quota.sql` после миграций парольной
авторизации и автоматического OTP. Таблица хешей и её RPC недоступны публичным
ролям. Лимиты 60 секунд, 5 запросов за час, 10 за день и
`CUSTOMER_OTP_DAILY_SEND_LIMIT` общие с автоматическим OTP; отказ отправки тоже
расходует лимит. Публичные маршруты дополнительно ограничены по IP.

SMS для восстановления пароля ограничены отдельно: максимум **2 запроса за
любые последние 24 часа на нормализованный номер**, включая повторную отправку.
Запросы одновременно из разных процессов сериализуются блокировками базы;
перезапуск сервера, новый request token, использование/истечение ссылки и
очистка таблицы ссылок не сбрасывают квоту. Следующий запрос доступен, когда
старейшая из двух попыток достигнет возраста 24 часа. Это не календарные сутки.
Регистрационные OTP не получают лимит 2: их существующие общие ограничения
сохраняются. Известные и неизвестные номера расходуют квоту одинаково.

Попытка учитывается после успешного резервирования в базе до вызова AutoCall.
Ошибка/таймаут провайдера и ошибка подтверждения доставки не возвращают попытку:
неопределённый результат может означать, что оплаченная SMS уже отправлена.
Отказ конфигурации до резервирования и отказ самой квоты не расходуют попытку.
При превышении сервер отвечает `429 PASSWORD_RESET_RATE_LIMITED` и передаёт
`Retry-After` и JSON `retryAfterSeconds`. Клиент сохраняет полученный срок
ожидания для соответствующего номера, учитывает его после возобновления приложения
и отображает длительные ожидания в часах/минутах; локальный счётчик отправок не
заменяет серверную проверку. При обновлении существующей установки миграция
учитывает время последней ещё сохранённой ссылки; более ранние удалённые запросы
до появления отдельной квоты восстановить по старой схеме невозможно.

Новый шаблон ссылки требует отдельной проверки AutoCall: одобрение SMS с кодом
не подтверждает одобрение текста с URL. Официальный SMS-раздел поддерживает
ссылки и переменные, но не гарантирует отсутствие повторной модерации для
меняющегося URL. Сервер ждёт только ограниченное время в существующем цикле
чтения статуса и активирует ссылку после `running` либо точного доказательства
доставки `completed` с теми же переменными. Долгая модерация, ожидание запуска,
отказ или таймаут удаляют неподтверждённый хеш и возвращают общую ошибку.
Если провайдер доставит SMS позже, её ссылка уже недействительна. Платный `POST`
автоматически не повторяется. Новый шаблон не проверен реальной отправкой в
рамках реализации; до заявления о готовности требуется согласованный тест
доставки на контролируемом номере.

## Защита и учёт

- Криптографически случайный код из 6 цифр, срок 5 минут и не более 5 попыток.
- В базе хранится HMAC кода, без открытого текста. В API-ответе код не возвращается.
- После успешной проверки код атомарно удаляется. Назначение кода и хеш пароля
  регистрации сохраняются только для соответствующего шага авторизации.
- Между отправками одному номеру минимум 60 секунд; не более 5 запросов за час
  и 10 за день. Ограничения сохраняются в базе между перезапусками сервера.
- `CUSTOMER_OTP_DAILY_SEND_LIMIT` ограничивает все автоматические отправки
  за календарный день базы; по умолчанию 1000. Неуспешные попытки тоже учитываются.
- Код становится доступен для подтверждения после принятия сообщения провайдером.
  Принятие запроса не является подтверждением доставки на телефон.
- При отказе провайдера клиент получает ошибку, неподтверждённый код удаляется.
  Таймаут не вызывает повторную отправку автоматически.
- Старые четырёхзначные коды бота продолжают проверяться для входа во время перехода;
  восстановление пароля ими недоступно.
- Перед включением платной отправки проверить защиту публичного API от массовых
  запросов на множество номеров и настроить дневной бюджет под фактический трафик.

## Проверка реализации

4 октября для SMS-ссылок восстановления прошли 93 целевых серверных теста:
одинаковые ответы для известных и неизвестных номеров, хеши и 15-минутный срок,
повторное и конкурентное использование, замена ссылки, смена номера и версии
пароля, откат транзакции, отзыв сессий, общие лимиты и публичные права доступа.
Проверены HTTP-контракты, закрытие старого OTP-восстановления, сокрытие ссылки
в обычных журналах и дочернем контексте, сохранение семейного восстановления,
регистрация и обычный вход. Гонка входа со старым паролем во время восстановления
закрыта: выдаваемая сессия привязана к версии, доказанной при проверке пароля,
и не получает новую версию после параллельного сброса. Проверка стиля кода прошла.

После добавления AutoCall прошли 36 тестов автоматического OTP и парольной
авторизации: формат SMS и WhatsApp-шаблона, выбор канала только для регистрации,
немедленный запуск по времени Казахстана и границу суток, ограниченное чтение
статуса без повторной отправки, отказ и модерация провайдера, скрытие секретов
в ошибках, истечение и однократное
подтверждение кода, конкурентные запросы, ограничения отправок, совместимость
старых клиентов и восстановление пароля. Проверки кода, секретов, размеров
исходников, API-контрактов и безопасности миграции также прошли. Полная серверная
проверка: 1750 тестов прошли, 5 штатно пропущены, ошибок нет.
3 октября владелец создал аккаунт AutoCall и разрешил постоянный ключ только
для регистрационных SMS. Ключ ограничен SMS-методами и IP сервера Bulka;
сохранён только в серверном окружении. AutoCall одобрил текст контрольной
рассылки, в профиле подтверждено окно 00:00–23:59:59 и цена 37,30 ₸ за сегмент.
Первое обновление установлено 3 октября. Контрольная SMS создана в 23:00:45,
отправлена оператору KCELL в 23:00:48 и получила статус «Доставлено» в 23:01:05;
получатель отдельно подтвердил получение. Проверка выявила переход из очереди
в `running` после ответа на создание; ограниченное ожидание промежуточных
статусов доработано перед следующей проверкой. На момент этой проверки 3 октября
регистрационный канал для клиентов не был включён: владелец выбрал только бесплатный
баланс 100 ₸ для тестов, без пополнения и общего запуска для клиентов. Решение
4 октября о включении регистрационных SMS описано в разделе AutoCall выше.
