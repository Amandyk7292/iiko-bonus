# iiko Dashboard в админке Bulka

Веб-раздел `/admin/iiko-dashboard`. Интерфейс: русский, казахский, английский. Доступ к финансовой отчётности только у owner/admin, проверяется сервером для каждого запроса.

## Источники

Основной источник города — его Chain: Актау `bulka-co.iiko.it`, Астана `bulka-astana-co.iiko.it`. Отдельные RMS выбираются для отчёта по конкретному серверу; данные Chain и RMS не складываются. Проверены обе учётные записи Chain и 18 действующих RMS.

Владелец подтвердил закрытие `bulka-atyrau-pristroyka-23a`, `bulka-dostavka`, `bulka-trc-aktau`. Они видны в реестре со статусом «Закрыт», исключены из выбора подключения. Серверный клиент отклоняет запрос до аутентификации. Исторические данные этих точек в Chain не фильтруются.

Учётные данные хранятся только в серверных переменных `IIKO_DASHBOARD_AKTAU_LOGIN/PASSWORD`, `IIKO_DASHBOARD_ASTANA_LOGIN/PASSWORD`. Отдельный RMS может переопределить городскую учётную запись через `IIKO_DASHBOARD_<SERVER_ID_WITH_UNDERSCORES>_LOGIN/PASSWORD`. Значения, хеши и сессии не отправляются в браузер и не входят в репозиторий. Только HTTPS на явный список хостов, запрет редиректов, таймаут, лимит размера, последовательные сессии каждого сервера и logout в finally.

## Реализовано

- Обзор: выручка, чеки, средний чек, скидки, себестоимость, гости, количество. Выбор и порядок карточек. График по дням, сравнение с предыдущим периодом или прошлым годом.
- Рейтинги филиалов внутри выбранного города и кассиров по кассирскому ID, имени и филиалу. Кассир не подменяется официантом. Выручка, сумма до скидок, чеки, количество, сумма скидки, количество со скидкой, себестоимость, среднее и доля скидки.
- Топ товаров с единицами измерения, группы товаров, продажи со скидками с названием акции. Топ-10, сортировка, поиск, постраничная таблица и сравнение периодов.
- Детализация: филиал → кассиры → проданные товары; товар → продажи по филиалам.
- Списания по филиалам, товарам и документам: склад, дата, товар, единицы, количество, стоимость, счёт списания и комментарий документа.
- Конструктор OLAP: продажи, проводки, доставка; поля фактической схемы iiko, до 5 группировок, 12 агрегатов, включающие/исключающие фильтры, пользовательские шаблоны.
- Остатки: склады, группы, количество и стоимость, минимумы/максимумы из iiko, фильтры отрицательных остатков и отклонений от норм.
- Excel для отчётов, рейтингов и остатков. Числа сохраняются числами, входные строки не выполняются как формулы.
- Автоматический повторный запрос раз в минуту при открытой вкладке, при возврате на неё и восстановлении сети. Это опрос отчётного API; задержка репликации RMS → Chain определяется iiko.

## Правила подсчёта

Продажи исключают удалённые заказы и удалённые строки. Средний чек = выручка / уникальные чеки, не среднее средних. При детализации по товарам это выручка выбранных товаров на чек; соответствующая подпись отличается от среднего полного чека. Отсутствующее значение не подменяется нулём. Чеки по разным товарам не суммируются.

Количество использует единицы iiko: штучные и весовые позиции. Таблица товаров показывает единицы; общий объём филиала/кассира может включать разные единицы. Поле количества со скидкой берётся из `ItemSaleEventDiscountType.DiscountAmount`. Несколько акций могут пересекаться на одной позиции; таблица скидок предупреждает о неаддитивности.

Списания: только `TRANSACTIONS`, `TransactionType=WRITEOFF`, `Account.StoreOrAccount=STORE`. Проводка по корреспондирующему счёту исключена, расход по обычным продажам (`SESSION_WRITEOFF`) не включён. Стоимость и количество инвертируют знаковое движение, сохраняя сторно; `abs()` не используется. Количество филиала группируется отдельно по единицам. Товары объединяются по ID, а не только имени.

## Проверки и границы

Backend-тесты: изоляция городских доступов, закрытые серверы, диапазон дат, проверка полей, последовательность/освобождение сессий, отсутствие секретов в ошибках, права на маршрутах, формулы Excel, подсчёт средних и списаний со сторно. Frontend: TypeScript, production build, модель периодов/пустых дней/настроек. Браузерная проверка использует локальную сессию владельца и реальные отчёты обоих Chain; изменения в iiko не выполняются.

Настройки карточек и шаблоны сохраняются в текущем браузере, предусмотрены JSON импорт/экспорт. Excel содержит данные, без встроенных графиков. Веб-раздел не реализует нативные виджеты iOS/macOS или отправку в Telegram. Произвольные финансовые показатели создаются через OLAP-конструктор; предустановленный P&L не подменяется выдуманными бухгалтерскими формулами. Это описание реализованной веб-аналитики, а не заявление о полном совпадении всех функций iOS-приложения.
