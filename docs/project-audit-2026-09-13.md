# Аудит проекта Bulka от 13 сентября 2026

## Итог

Критических дефектов уровня P0, которые прямо сейчас подтверждают потерю денег или данных, не найдено. Основные цепочки заказа защищены тестами, production отвечает штатно, а мобильная и административная кодовые базы проходят свои полные тесты.

Проект пока нельзя считать полностью готовым к эксплуатации без наблюдения. До следующего функционального релиза нужно закрыть четыре проблемы P1: обновить уязвимые серверные зависимости, включить обязательный CI на изменения, уменьшить и сжимать Flutter web bundle и определить единственную чистую рабочую копию для релизов.

## P1 — исправить до следующего релиза

### 1. Уязвимые production-зависимости backend

`npm audit --omit=dev` обнаружил две high, одну moderate и две low уязвимости. Существенные для этого проекта:

- `multer 2.2.0`: high, несколько сценариев отказа в обслуживании; библиотека обрабатывает публичные загрузки изображений и файлов. Исправление доступно в 2.3.0.
- `sharp 0.35.3`: high в обработке HEIF; код обрабатывает полученные изображения. Исправление доступно в 0.35.4.
- `adm-zip 0.6.0`: moderate, небезопасная обработка символьных ссылок. Исправление доступно в 0.6.1. Текущий код в основном создаёт архивы, поэтому практический риск ниже.
- Две low приходят транзитивно через `joi`/`passkit-generator` и требуют отдельной проверки совместимого обновления.

Файл: `package.json`, строки 34, 49, 52 и 57.

Рекомендация: обновить первые три пакета отдельным изменением, повторить полный backend suite и проверить реальные загрузки JPG, PNG и HEIF.

### 2. CI существует, но не запускается на push и pull request

В `.github/workflows/ci.yml` оставлен только `workflow_dispatch`; в самом файле указано, что автоматизация отключена. При этом workflow содержит нужные проверки: audit, CodeQL, backend, admin E2E и Flutter test. Сейчас ошибочный commit может попасть в `main` без единого автоматического gate.

Рекомендация: вернуть запуск на pull request и защитить `main`, потребовав успешные jobs `node`, `codeql`, `admin-e2e` и `flutter`.

### 3. Flutter web загружается тяжело и без HTTP-сжатия

Production `main.dart.js` имеет размер 6 247 771 байт. Ответ на запрос с `Accept-Encoding: br` не содержит `Content-Encoding` и отдаёт полный `Content-Length: 6247771`. Дополнительно renderer содержит WASM-файлы по 3.5–7.1 MB. Это увеличивает холодный запуск, особенно на мобильной сети.

Рекомендация: включить Brotli/Gzip для JS, WASM, CSS и JSON в nginx, оставить версионные URL, затем измерить LCP и время до первого интерактивного экрана на реальном iPhone/Android через 4G.

### 4. На компьютере две расходящиеся рабочие копии

Исходная папка `C:\Users\Asus Rog\Desktop\bulkaiiko-bonus-system` отстаёт от `origin/main` и содержит много незакоммиченных файлов. Текущая production-версия находится в чистой копии `C:\Users\Asus Rog\AppData\Local\BULKA\iiko-invoices-deploy-20260913`. Случайный релиз из старой папки способен вернуть исправленные баги или смешать несовместимые изменения.

Рекомендация: сохранить нужные незакоммиченные изменения отдельной веткой, после проверки удалить устаревшую копию из релизного процесса и публиковать только из чистого `main`, совпадающего с `origin/main`.

## P2 — функциональные и UX-проблемы

### 5. Карточка отсутствующего товара не открывается

В `BulkaAndroid/lib/screens/catalog_product_card.dart` строки 71–73 и 233 отключают оба `onTap`, когда товар в stop-list. Пользователь не может посмотреть состав, аллергены и описание. Кнопка добавления уже отдельно блокируется, поэтому карточку можно открывать безопасно.

Исправление: разрешить открытие деталей независимо от наличия, оставить отключёнными только добавление и увеличение количества, показать в деталях явный статус «Нет в наличии».

### 6. «С этим часто покупают» за последние 30 дней не реализовано

`src/services/personalization.service.js` строит персональные рекомендации из избранного, просмотров и последних 30 заказов конкретного клиента. Это количество заказов, а не окно в 30 дней и не анализ товаров, купленных вместе с открытым товаром. Flutter-клиент имеет метод API рекомендаций, но экран деталей его не использует.

Исправление: считать пары товаров в оплаченных заказах за последние 30 дней, исключать текущий товар и stop-list, учитывать выбранный филиал, возвращать fallback по популярности филиала и вывести горизонтальный блок внизу деталей.

### 7. Гостевой клиент создаёт две ожидаемые ошибки 401

При каждом гостевом открытии production вызываются `/admin/api/session` и `/api/auth/refresh`; обе проверки возвращают 401 и попадают в console как ошибки. Авторизация не ломается, но шум затрудняет мониторинг настоящих проблем и делает лишние запросы.

Исправление: не проверять административную сессию на клиентских маршрутах; для customer refresh различать ожидаемое отсутствие сессии и сетевую ошибку без записи в error console.

### 8. iiko Dashboard делает лишний отчёт каждую минуту на всех вкладках

Автообновление включено по умолчанию. `IikoDashboardPage.tsx` строки 132–147 увеличивает `refresh` раз в 60 секунд, а эффект строк 152–176 запрашивает список подразделений без проверки активной вкладки. Поэтому запрос отчёта выполняется даже в «Настройках», «Накладных» и «Остатках».

Исправление: загружать подразделения только для вкладок, где используется фильтр, и не перезапрашивать неизменяемый справочник каждую минуту.

### 9. Состояние iiko Dashboard отсутствует в URL

Выбранные вкладка, период, сервер, подразделение и поставщик хранятся только в React state. Обновление страницы, Back и отправленная коллеге ссылка теряют контекст.

Исправление: синхронизировать параметры с query string, например `?tab=invoices&server=...&from=...&to=...&supplier=...`.

### 10. Пустая корзина использует сообщение об ошибке поиска

Актуальный исходник показывает «Ой! Ничего не найдено!» и только кнопку перехода в каталог. Это выглядит как сбой, не объясняет пустую корзину и не содержит показанного на старом скриншоте блока популярных товаров.

Исправление: текст «Корзина пока пуста», короткое пояснение и корректный блок рекомендаций. Нажатие общей кнопки должно открывать корень каталога; карточки рекомендаций — только выбранный товар.

### 11. Возможен пустой источник после удаления city-chain сервера

Первичная загрузка правильно выбирает первый активный сервер. При переключении города часть логики формирует ID вида `${city}-chain`; если chain удалён, но отдельные серверы города активны, выбранный источник становится неопределённым.

Исправление: выбирать активный chain выбранного города, иначе первый активный RMS-сервер этого города.

### 12. Мелкий текст в административном интерфейсе

В стилях операций, WhatsApp, глобального поиска, релизов и Taplink много подписей размером 9–11 px. Они плохо читаются на планшете и при работе кассира. Основная страница входа при этом проходит axe и адаптируется корректно.

Исправление: установить минимум 12 px для вторичных технических меток и 14 px для интерактивного текста; проверить 200% zoom и ширины 320, 390, 768 и 1440 px.

## P3 — технический долг

- 86 Flutter-пакетов имеют более новые версии вне текущих ограничений. `pub outdated` не отметил используемые версии как затронутые известными advisory, поэтому это плановое обновление, а не текущая уязвимость.
- Несколько файлов превышают 1500–3500 строк, включая `yandex-delivery.service.js`, `forte-widget.service.js`, `admin-ui/src/index.css`, `bulka_api_client.dart` и `stories.dart`. Проверка размера проходит только благодаря ratchet-исключениям; изменения в этих файлах дороже проверять.
- В `admin-ui/src/main.ts` и `counter.ts` остался стартовый пример Vite. Он не входит в рабочую точку входа, но создаёт ложный след для разработчика.
