# Закрытие аудита проекта

Дата проверки: 26 июля 2026 года.

## Что исправлено

### Безопасность и персональные данные

- Управление клиентами переведено с доступа к разделу на разрешения по действиям.
- Удаление клиента разрешено только владельцу и администратору и выполняется через безопасный privacy-процесс.
- Для ручных бонусных операций обязательна причина; добавлены лимиты и тесты матрицы ролей.
- Токены чеков скрываются в access-логах, подписи имеют срок действия.
- Административные JWT отделены от клиентских; добавлены серверные отзывные сессии.
- Аудит административных действий стал структурированным и неизменяемым на уровне базы данных.
- Все ответы HTTP 500 очищаются от внутренних сообщений и получают `requestId`.
- Загрузка JPEG, PNG и WebP всегда декодирует и перекодирует изображение без metadata, проверяет число пикселей и отклоняет анимацию.
- Экспорт и удаление персональных данных охватывают связанные хранилища и выполняются согласованно.

### API, миграции и эксплуатация

- Добавлены общие Zod-контракты для критических административных и клиентских API.
- Включена глобальная защита тела запроса от чрезмерного размера, глубины, числа ключей и prototype pollution.
- Оставлен один канонический каталог неизменяемых миграций; snapshot исключён из checksum-ledger.
- Добавлена автоматическая проверка конфликтов и изменения уже применённых миграций.
- Релиз на VPS использует манифест и checksum, проверяет `/readyz` и поддерживает rollback.
- Добавлены структурированные логи, correlation ID, метрики, readiness фоновых задач и webhook-оповещения.

### CI, зависимости и мобильные сборки

- CI запускает backend, admin Vitest/Playwright, Python QA, Flutter analyze/test/coverage/web, Android APK/AAB и iOS build без подписи.
- Добавлены CodeQL, npm audit для трёх Node-проектов и генерация SBOM.
- `react` и `react-dom` зафиксированы прямыми зависимостями admin UI.
- Уязвимые версии `body-parser` и `brace-expansion` устранены.
- Сгенерированные `admin-ui/dist` и `public/app` исключены из Git и собираются в CI.
- Добавлены лимиты размера bundle, исходных файлов и минимального покрытия.

### Интерфейс и поддерживаемость

- Исправлены загрузка административных страниц без ручного обновления и восстановление после устаревшего frontend chunk.
- Локации сгруппированы и фильтруются по городам; добавлены создание города на карте и создание точки внутри города.
- Состояния фильтров и вкладок сохраняются в URL, навигация использует ссылки.
- Добавлены языковое состояние, сохранение выбора языка, корректный `document.lang` и проверки доступности Axe.
- Для наиболее крупных файлов введены ratchet-лимиты, не позволяющие им снова расти.
- Политика конфиденциальности дополнена WhatsApp/Meta и используемыми AI-провайдерами.
- Назначение Device ID в iOS privacy manifest исправлено на функциональное использование приложения.

## Действия при production-релизе

1. Применить миграции `20260726120000_privacy_lifecycle_hardening.sql` и `20260726121000_admin_session_audit_hardening.sql`.
2. Задать отдельные сильные значения `ADMIN_JWT_SECRET` и `METRICS_BEARER_TOKEN`.
3. При необходимости настроить `OPS_ALERT_WEBHOOK_URL`.
4. Если старые production access-логи содержали URL чеков с токенами, сменить `RECEIPT_SIGNING_SECRET`.
5. Для публикации iOS выполнить подписанный archive на macOS с действующими сертификатами Apple. CI уже проверяет компиляцию без подписи.

Абсолютное покрытие admin UI пока невысокое, но теперь измеряется по всему исходному коду и защищено минимальными порогами. Его следует повышать постепенно вместе с новыми изменениями.
