# Внешняя оплата Bulka онлайн — плагин 1.8.0

Сначала обновите плагин на кассах филиала и запустите iikoFront. Затем в iikoOffice откройте «Розничные продажи → Типы оплат», обновите список и создайте один тип оплаты. Он применяется к уже оплаченным заказам Bulka, включая самовывоз и доставку.

| Поле | Значение |
| --- | --- |
| Наименование | Bulka онлайн |
| Тип | Внешний тип оплаты |
| Название в чеке | Bulka онлайн |
| Безналичный тип / обработчик | Bulka онлайн |
| Запрещать вводить вручную | Включено — платёж добавляет плагин |
| Можно комбинировать с другими типами оплаты | Выключено |
| Применять для всех категорий блюд | Включено |
| Печатать товарный чек | Выключено; можно включить для дополнительного бумажного товарного чека |
| Открывать денежный ящик | Выключено |
| Устанавливать точную сумму | Включено |
| Может приниматься извне | Выключено / оставить неактивным |
| Проведение оплаты | Только на стороне ресторана |
| Код | Оставить пустым |
| Счёт выручки | Существующий «Торговая выручка без учета скидок» |
| Счёт поступления денег | Существующий «Денежные средства, эквайринг» |
| Проводить как скидку | Выключено |

**«Является фискальным»** отвечает за формирование фискального чека в iiko. Веб-приложение Bulka формирует торговый чек, который не является фискальным. Если фискальный чек этой покупки оформляет касса iikoFront, этот флажок включается. Если покупка уже фискализируется отдельной онлайн-кассой, настройку необходимо согласовать с действующей схемой, чтобы не оформить продажу повторно. Плагин не меняет этот флажок, налоги или настройки фискального регистратора.

Название «Bulka онлайн» в нижнем списке появится после успешной регистрации платёжной системы новым плагином на кассе. Если его нет, проверьте версию, журнал запуска плагина и лицензию iiko на внешние платёжные системы. Другой обработчик (Halyk, Kaspi, Pax и т. п.) к этому типу не подходит.

После сохранения дождитесь синхронизации настроек с каждой кассой. Новые выданные онлайн-заказы попадают в очередь чеков. Одна касса создаёт товарный чек, переносит товары и онлайн-скидки, проверяет оплату на сервере Bulka и закрывает чек своим внешним обработчиком. Повторного обращения к эквайрингу нет. Статус или причина задержки чека видны на карточке заказа.

Проверять нужно на новом заказе: старые выданные заказы автоматически задним числом не пробиваются. При сбое кассы очередь сохраняется. Стоимость доставки учитывается отдельно и в товарную сумму этого чека не входит.

Документация iiko: [регистрация внешнего обработчика](https://iiko.github.io/front.api.doc/v6/ru/PaymentProcessor.html), [параметры типов оплаты](https://ru.iiko.help/resources/Storage/archive/PDF/RU_iikoOffice_7.3.pdf).
