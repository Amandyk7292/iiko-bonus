# Bulka для сотрудников Windows

Приложение открывает действующий сайт `https://bulka.com.kz/?desktop=1` в отдельном окне с упакованным браузером Supermium. Данные и функции приходят с действующего сайта. Интернет нужен для операций. .NET, Electron, WebView2 и установленный системный браузер не требуются.

## Установка

Запустите `Bulka-Staff-Setup-1.0.1-Universal.exe`. Установщик выбирает родной launcher x86 для 32-разрядной Windows и x64 для 64-разрядной. Обе архитектуры используют один проверенный 32-разрядный браузер Supermium; на 64-разрядной Windows он работает через штатный WOW64. Приложение устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\Bulka Staff`, без запроса прав администратора. Создаются ярлыки в меню «Пуск», а ярлык рабочего стола можно выбрать при установке.

Минимальная версия установщика и native launcher — Windows 7 (`6.1`); рекомендуются SP1 и все доступные обновления Windows. Также предусмотрены Windows 8/8.1/10/11. Реальная проверка на Windows 7 требуется отдельно: локальная сборка и запуск на современной Windows не заменяют испытание на старой ОС. Совместимость процессора и драйверов определяется поставляемой версией Supermium; версия и официальные источники записаны в `runtime-lock.json`.

Профиль браузера всегда находится в `%LOCALAPPDATA%\Bulka\Staff\Profile`. Установка, обновление и удаление приложения не удаляют профиль, cookies или вход. Перед обновлением нужно закрыть окно приложения; установщик также проверяет mutex приложения и использование файлов браузера. Выйдите из учётной записи внутри Bulka, когда заканчиваете работу на общем компьютере.

Обычный ярлык возвращает существующее окно на передний план. Для восстановления после потери интернета нажмите F5 либо «Пуск → Bulka → Восстановить соединение»: этот ярлык перезагружает уже открытое окно, сохраняя тот же профиль. Перезагрузка страницы может сбросить неотправленные изменения формы. После полного закрытия повторный запуск снова открывает актуальную страницу сайта.

Sandbox браузера и проверка TLS включены штатно. Приложение не принимает произвольный URL, пароль или токен в параметрах запуска. Упакованный браузер не регистрируется системным браузером по умолчанию.

## Точная сборка

Требуются PowerShell 5.1 или новее, C++ toolset VS2019 v142, Windows SDK 10.0.19041.0 и Inno Setup 6.7.3. Скрипт ищет существующие локальные компоненты; .NET требуется только на машине сборки для чтения ZIP и не является зависимостью поставляемого приложения.

Из корня репозитория:

```powershell
& .\scripts\build-windows-staff.ps1
```

Для существующего отдельного cache:

```powershell
& .\scripts\build-windows-staff.ps1 -RuntimeCacheDirectory 'C:\Users\Asus Rog\Desktop\bulkaiiko-bonus-system\outputs\windows-staff-2026-10-03\runtime-cache'
```

`-SkipDownload` разрешает только уже имеющиеся архивы с корректными SHA256. `-OutputDirectory` должен обозначать новую, ещё не существующую папку внутри текущего репозитория. По умолчанию создаётся новая папка с датой и случайным суффиксом в `outputs`. Старые сборки и cache никогда не удаляются.

Скрипт проверяет фиксированные официальные HTTPS URL и SHA256 из lock, отклоняет опасные пути и символьные ссылки в ZIP, извлекает файлы только в новую build-папку, компилирует оба launcher со статическим CRT, проверяет PE imports и собирает один универсальный установщик. Упаковывается только x86 browser runtime; его PE machine проверяется как `0x14c`. Проверенная запись x64 остаётся в lock как история источников и не включается в установщик. В `release` находятся EXE, SHA256 и отчёт с явным `runtimeArchitecture=x86` и использованием WOW64 на x64 Windows. Папка `payload\x86` содержит launcher с общим runtime; `payload\x64` содержит родной x64 launcher для установщика.

Используются `/MT`, `WINVER=0x0601`, `_WIN32_WINNT=0x0601` и `/SUBSYSTEM:WINDOWS,6.01`. Проверка imports отклоняет CLR, динамические VC/UCRT зависимости и API-set DLL у launcher. Лицензии runtime сохраняются, а сведения об официальном исходном коде и лицензии включаются в поставку. Иконка взята из существующего приложения Bulka Price Printer.

## Проверка сборки

`test-launcher.ps1 -LauncherPath <полный путь к payload\x86 либо x64\BulkaStaff.exe> -FixtureArchitecture x86` проверяет настоящий native launcher с отдельным 32-разрядным тестовым компонентом: фиксированный URL, профиль, безопасные параметры и повторное открытие того же окна. Отчёт показывает PE machine launcher и тестового компонента; x64 launcher → x86 компонент проверяет запуск через WOW64. Тестовый компонент остаётся за пределами экрана; его собственные процессы завершаются после проверки. Это проверка контракта launcher, а не web-интерфейса.

`test-installer.ps1 -InstallerPath <полный путь к универсальному EXE>` проверяет блокировку установки при активном mutex приложения, установку для текущего пользователя в новую папку `outputs`, выбор родного launcher, общий браузер PE `0x14c`, совпадение байтов с x86 browser payload и сохранение профиля после удаления приложения. Скрипт отказывается запускаться, если уже зарегистрирована обычная установка Bulka Staff. Успешный тест удаляет только свою установку и свой уникальный тестовый маркер; журналы и предыдущие сборки сохраняются.

`test-runtime.ps1 -PayloadDirectory <полный путь к payload> -SiteUrl http://127.0.0.1:58334/?desktop=1` запускает настоящий общий x86 браузер с пустым временным профилем и сохраняет снимок локального интерфейса. Отчёт указывает архитектуру ОС и WOW64. Допускается только локальный адрес; вход в систему и операции с данными не выполняются. Наличие PNG само по себе не подтверждает загрузку Flutter: каждый снимок необходимо просмотреть. `-VirtualTimeBudget 0` и `-DisableGpu` позволяют проверить диагностические сценарии; эти параметры не меняют штатный launcher и не отключают sandbox или TLS. `-Architectures x64` остаётся для диагностики ранее сохранённых сборок с отдельным x64 runtime.

Установщик пока не подписан сертификатом издателя; Windows может показывать «Неизвестный издатель». Публикация или загрузка на сервер не входит в этот скрипт.
